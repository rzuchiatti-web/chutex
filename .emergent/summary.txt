**original_problem_statement**: The user wants to build a comprehensive health monitoring and teleassistance application named VitalLink.

PRODUCT REQUIREMENTS:
- **UI/UX**: A modern, ultra-clinical, black-and-white design.
- **Health Monitoring**: Track user health data (e.g., Kcal, steps) with AI-powered recommendations for goals and alert thresholds. For now, this data is simulated.
- **Prescription Management**:
    - Admins can create prescriptions.
    - When a prescription is created, an email is sent to the user inviting them to subscribe to a service via a link.
    - The system should track the subscription status and manage commissions.
- **Guardian/Beneficiary Linking**: Beneficiaries must be able to share their health data with guardians. This should be done via a unique code or by scanning a QR code if they are physically together.
- **Guardian Dashboard**: Guardians should have a complete dashboard view of their linked beneficiary's data, including AI recommendations and the ability to generate a cumulative health report with AI analysis.
- **Teleassistance IA Protocol (Fully Automated)**:
    1.  An alert is triggered (e.g., SOS button on the app).
    2.  The system must **automatically** start an AI-powered call protocol without any manual action from an operator.
    3.  The IA calls the beneficiary using a doubt-lifting script (e.g., Is everything okay? What is happening?).
    4.  If the beneficiary does not answer, the IA automatically calls the registered guardians in a predefined order.
    5.  If no guardians answer, the system dispatches the nearest Intervention Provider partner.
    6.  The teleassistance dashboard must show a real-time log of the ongoing escalation (who is being called, call status, etc.).
- **Intervention Provider Role**:
    - A special role for partners who perform on-site interventions.
    - This role can be assigned to a user account from the back office using a special code.
    - When dispatching an intervention, the system must select the closest provider based on a configurable kilometer radius set in the back office.
- **Intervention Tracking**: Guardians and operators must be able to follow the dispatched intervention on a live map, similar to Uber Eats' delivery tracking.
- **Real-World Testing**: The user wants to test the full flow with real phone numbers for the beneficiary () and guardians (, ). The Twilio integration must use real calls.
